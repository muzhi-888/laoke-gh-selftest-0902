# 清洗后质检 SOP（Standard Operating Procedure）

基础脚本跑完只是第一步。这份 SOP 是「交付前最后一道关」，确保干净表真的能用。覆盖脚本未自动处理的几项关键质检。

## 一、质检总流程

```
原始表 → 基础脚本清洗 → 质检报告(脚本) → 进阶质检(SOP) → 人工签发 → 交付
```

进阶质检分四步：缺失复核、异常值检测、主键唯一性、跨列逻辑校验。

## 二、缺失复核

- 看报告「字段概览」的缺失率。
- 红线：关键列（ID、金额、日期、主键）缺失率 > 0 就要追因，> 5% 这份表本身有问题。
- 处置：缺失少的填策略（见 references/03）；缺失多的回源重导，勿硬洗。

## 三、异常值检测（Z-Score / 分位数法）

脚本不自动改异常值，但应标出让你看：

- **数值列**：计算均值 μ 与标准差 σ，超出 `[μ-3σ, μ+3σ]` 的记为异常候选；或看 1%/99% 分位数外的极端值。
- **常见真异常**：年龄 0/999、价格 -1/负数、占比 >100%、日期在未来 50 年或早于 1900。
- **处置三选一**（让用户定）：
  1. 截断（winsorize）到分位数；
  2. 置空（当缺失处理）；
  3. 直接剔除该行（记录删了多少）。

> 注意：异常≠错误。销售额 999 万可能是真大单。务必先报告再处理，别一刀切。

## 四、主键唯一性校验

- 取业务主键列（订单号/用户ID），检查是否唯一。
- 不唯一 → 报告重复值清单，交人工判断是「真重复」还是「业务允许的多次记录」。
- 绝不由脚本决定删哪条。

## 五、跨列逻辑校验

这些「列与列之间矛盾」的脏数据，基础脚本发现不了：

- 开始日期 > 结束日期。
- 「是否在职=否」但「离职日期为空」。
- 「数量×单价 ≠ 金额」（允许小额舍入误差）。
- 「年龄 < 18」却「工作年限 > 10」。
- 省份与城市不匹配（如省份=浙江，城市=北京）。

实现：写一组断言（assert / if），命中即列出「行号 + 冲突列 + 冲突值」，交人工。

## 六、质检报告模板（进阶）

在脚本报告基础上追加：

```markdown
## 进阶质检

### 异常值候选
| 行 | 字段 | 值 | 说明 |
| --- | --- | --- | --- |
| 42 | 年龄 | 999 | 超 3σ，疑似录入错误 |

### 主键唯一性
- 订单号：发现 3 个重复值（行 10/11/88），需人工核对

### 跨列逻辑冲突
| 行 | 冲突 |
| --- | --- |
| 7 | 开始(2023-05-01) > 结束(2023-04-01) |

### 签发结论
□ 通过，可直接使用  □ 需返工（列明待办）
```

## 七、交付留痕

- 干净表 + 基础报告 + 进阶质检，三件套一起给。
- 记录本次使用的参数（占位符清单、单位换算、缺失策略），下次复跑可复用。
- 提示用户：源文件未改动；敏感字段已脱敏/建议删除临时文件。
- 若数据将进入生产系统，建议保留「原始表哈希值」作为溯源凭证。
