# 清洗规则与标准化清单

本文件给出「基础脚本之外」的常用清洗规则，供 AI 针对具体表格生成补充脚本时参考。所有规则遵循同一原则：**可解释、可回滚、不改源文件**。

## 一、表头规范（建议落库标准）

- 命名：小写蛇形或小写中文，无空格、无全角。例：`user_id`、`order_no`、`客户名称`。
- 长度：建议 ≤ 30 字符，避免数据库列名超限。
- 禁止：空格、斜杠、括号、保留字（`select`、`order`）。如有，加前缀或转义。
- 重名：自动加 `_2`/`_3` 后缀并提示用户确认语义。

## 二、缺失值处理策略（必须用户拍板）

| 策略 | 适用 | 风险 |
| --- | --- | --- |
| 保留空 | 大多数分析场景 | 最低，推荐默认 |
| 填众数/均值 | 数值列、缺失少（<5%） | 可能掩盖分布偏差 |
| 填固定哨兵（如 -1、1900-01-01） | 需占位但不参与计算 | 须在文档标注哨兵含义 |
| 整行删除 | 关键列缺失且缺失多 | 可能丢样本，需记录删了多少 |
| 插值（前后填充） | 时间序列 | 仅适合有序数据 |

**铁律**：脚本绝不擅自编造「看起来合理」的值。缺失=缺失，处理方式必须由用户确认后写入报告。

## 三、枚举/分类值规范化

把同一含义的不同写法统一：

- 性别：`男/男性/M/先生` → `男`；`女/女性/F/女士` → `女`。
- 是否：`是/Y/YES/true/√` → `是`；`否/N/NO/false/×` → `否`。
- 省份/城市：统一用标准行政区划名（避免「北京」「北京市」「bj」混用）。
- 状态：`已付款/支付成功/paid` → 统一 `已付款`。

实现：建一张 `{原始写法: 标准值}` 映射表，遍历替换；未命中项报告出来让用户补词库（不要猜）。

## 四、单位统一

- 长度：`1.8米`、`180cm`、`1800mm` → 统一为 `cm`（数值 180）。
- 重量：`2kg`、`2000g` → 统一 `g`。
- 金额：`1.2万`、`12000`、`1.2万元` → 统一「元」（数值 12000），剥离「万/元」单位词。
- 实现：正则提取数值+单位，按换算系数归一；单位词单独存一列或直接丢弃（视需求）。

## 五、分列与合并

- 分列：「北京市-朝阳区」拆成「城市」「区」两列（按分隔符 split）。
- 合并：「省+市+区」拼成标准地址。
- 注意：分列前确认分隔符在值内不出现（否则会多拆），可用引号包裹或换更安全分隔符。

## 六、去重策略分级

| 级别 | 定义 | 是否自动 |
| --- | --- | --- |
| L0 整行完全重复 | 所有列逐格相等 | 自动删，留首条 |
| L1 业务主键重复 | 主键列相等，其他可能不同 | 仅报告，人工定 |
| L2 近似重复 | 关键字段相似（如地址差一个字） | 提示，需模糊匹配，人工定 |

## 七、标准化检查清单（交付前）

- [ ] 表头无空格/全角/保留字
- [ ] 数值列已无货币符/千分位
- [ ] 日期统一 `YYYY-MM-DD`
- [ ] 枚举已映射为标准值，未命中项已列出
- [ ] 单位已统一并标注
- [ ] 缺失策略已确认并记录
- [ ] 去重级别已确认（L0 自动 / L1 L2 人工）
- [ ] 所有改动写入质检报告
