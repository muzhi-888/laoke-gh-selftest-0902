# 字段类型推断与转换

类型推断是「能进图表/入库不报错」的前提。类型错了，Excel 把数字当文本、数据库建错列、模型读到字符串——全是坑。

## 一、五类基础类型

| 类型 | 判断依据 | 存储建议 |
| --- | --- | --- |
| int | 全为整数数字，无小数点 | 整数列 |
| float | 含小数点且可转 float | 金额、比率、计量 |
| date | 匹配 `YYYY-MM-DD` 等日期格式 | 日期列（统一 ISO） |
| bool | 是/否/true/false/y/n 等 | 标志位 |
| string | 以上都不是 | 名称、文本、编码（如电话号、邮编——**注意陷阱**） |

## 二、推断算法（参考脚本实现）

对每列取非空样本：
1. 若 ≥80% 样本匹配整数/小数正则 → 判 int/float（看有没有小数点）。
2. 否则若 ≥80% 匹配日期格式 → 判 date。
3. 否则若样本落在布尔词表 → 判 bool。
4. 否则 → string。

阈值 80% 是经验值：允许少量脏样本（如某格混了「待定」）不致命，但会触发「该列被推成 string」的提示，让用户去查那几个脏格。

## 三、两个经典陷阱

### 陷阱 1：电话号/身份证/邮编被当数字
这些虽是数字，但**不能当数值**（前导 0、不参与加减）。必须保持 string。若被推断成 int，前导 0 会丢、15 位以上精度会失。
**处置**：这类列在推断后强制改回 string，或在类型映射里加「列名白名单」（含「电话/手机/身份证/邮编/账号」的列一律 string）。

### 陷阱 2：金额含货币符被当 string
`￥12,000` 直接判 string。必须先剥离符号与千分位再判数值。
**处置**：脚本的 `normalize_cell` 在去空格后、类型判断前，先做货币/千分位/括号负数/百分比还原。

## 四、日期统一格式化

源格式千奇百怪，目标统一为 ISO `YYYY-MM-DD`：

- `2023/1/5` → `2023-01-05`（月日补零）
- `2023.01.15` → `2023-01-15`
- `23年1月15日` → `2023-01-15`（两位数年份按 2000+ 处理，需谨慎）
- `January 15, 2023` → `2023-01-15`（英文月需映射表）

实现建议：用 `datetime.strptime` 配多格式尝试，成功即转 ISO；全失败则该格保留原值并标记，交人工。

## 五、布尔归一

| 原始 | 标准 |
| --- | --- |
| 是/YES/true/Y/√/有/已 | 是 |
| 否/NO/false/N/×/无/未 | 否 |

注意「空」与「否」不同：空是缺失，否是明确否定，别混。

## 六、类型转换落库建议

- 清洗后的 CSV 直接进数据库时，按推断类型建表（int→INTEGER、float→REAL、date→DATE、bool→BOOLEAN、string→TEXT）。
- 字段概览表（脚本报告里的 per_column）就是现成的建表 schema 草稿。
- 转换前先确认：数值列有没有「单位」藏在值里（如 `180cm`），有的话先分离单位再转数值。
